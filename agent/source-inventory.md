# Installed Source Inventory

This inventory describes the source sets expected in a public installed `pire-browser` package. It is not a repository file listing.

## Authoritative Installed Source Sets

- `bin/pire-browser.js`: public JS launcher that selects the optional native package.
- `pi/extensions/`: Pi extension wrapper and runtime helpers used by coding agents.
- `extension/manifest.json` and `extension/dist/`: Firefox extension manifest and built background assets.
- `agent/`: compact routing guidance for installed agents.
- `pire-browser.schema.json`: authoritative packaged config schema for `pire-browser` defaults, including launch args/User-Agent defaults, screenshot-capture defaults, and credential-provider plugin entries.
- `agent-browser.schema.json`: legacy packaged schema filename alias kept for existing configs; mirrors the supported config keys including launch, screenshot, and `plugins` defaults.
- `skills/pire-browser/SKILL.md`: small discovery stub for skill installers and agents.
- `skill-data/core/SKILL.md`, `skill-data/core/references/full.md`, and `skill-data/dogfood/SKILL.md`: version-matched compact core, opt-in extended core reference, and exploratory QA guidance served by `pire-browser skills cat/get/path <name>`; `skills get core --full` selects the extended reference. The JS launcher can serve this guidance even when native setup needs repair. `PIRE_BROWSER_SKILLS_DIR` and `AGENT_BROWSER_SKILLS_DIR` can override the runtime skill root for local development.
- `bin/pire-browser.js`, `scripts/pi-postinstall.mjs`, `scripts/pi-install-migration.mjs`: launcher-served `pi conflicts`/`pi repair` duplicate-source recovery, best-effort postinstall setup, old direct extension shim cleanup, and verified old Pi-managed GitHub checkout quarantine.
- `package.json`: npm/Pi package metadata. Native binaries are version-matched optional dependencies, and Pi core runtime imports are optional peers provided by Pi hosts rather than direct CLI installs.
- `LICENSE`: MIT license terms for the public package.
- `README.md`: public package overview and human-facing install notes.

## Generated Or Runtime Artifacts

- Native messaging manifests and registry entries are generated by `pire-browser setup`.
- Native binaries are supplied by optional platform packages such as `@ryenw/pire-browser-win32-x64`, not by the root npm package.
- Live-session metadata, compact automatic restore state, encrypted auth vault/key files, confirmations, uploads, policies, Firefox profiler JSON bundles, screenshot-sequence recording bundles, dashboard state/log files, and bounded redacted activity logs live under standard OS state directories or explicit output directories, not in the npm package.
- Ordinary session profiles and default downloads live below a marked OS temporary root and are deleted only through marker-validated cleanup. Named Firefox profile sources are copied into temporary snapshots; explicit profile paths and preserved 0.2.x profiles are durable and are never swept automatically.
- Automatic restore files live under `restore-sessions/<namespace>/<key>.json`. Current schema v2 contains all profile cookies plus origin-keyed `localStorage`; legacy active-origin v1 files remain readable.

## Excluded Maintainer Material

The public npm package should not ship repository-maintainer context such as `docs/`, repository test fixtures, or Pi tests. Those files are useful for development but noisy for installed agents.

## Known Ambiguity

- The installed package is version matched to its embedded skill content. If an agent sees local docs outside this installed package, prefer the files listed above unless the user explicitly asks for maintainer or repository context.
- State schema v2 is current. Schema v1 remains a read-compatible legacy format; future schema bumps require migrations or clear unsupported-version errors.
