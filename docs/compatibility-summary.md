# Compatibility Summary

This is a public, product-facing status summary for `pire-browser@0.3.0-beta.2`. Detailed private development records are not published in this repository.

| Area | Status | Notes |
| --- | --- | --- |
| Install and setup | Supported | Global, project, npx one-off trial, and source installs are documented for the Firefox-backed package. Stable and 0.3 beta installs are explicit; updates follow the installed npm channel and apply an exact registry version, with a documented return-to-stable command. Pi core imports are optional peers while the default `web-ext` launch helper is a normal runtime dependency so fresh installs do not need a surprise `npx` registry fetch before the first browser command. `install --with-deps` accepts agent-browser-style setup recipes, can install Firefox through winget/Chocolatey on Windows or Homebrew on macOS when missing, and reports non-Snap/non-Flatpak guidance on Linux; launcher-served help and diagnostics report concrete optional-native-package repair guidance, and `doctor --fix` provides explicit setup repair. |
| MCP and chat agent integration | Partial | `pire-browser mcp --tools core` exposes a 31-tool, one-page inspect-before-act workflow with open/read/snapshot, common actions, narrow waits, screenshots, tabs, history, targeted verification, eval, close, and approval follow-up. Advanced tools and compatibility aliases remain available through comma-combined `network`, `state`, `debug`, `tabs`, `mobile`, and `react` profiles or `all`. `skills get core` returns a compact version-matched workflow, while `--full` returns the extended reference. CI enforces byte/token budgets and npm/Cargo server-version alignment against a built native binary. An optional live agent eval harness scores first-use, form, tab/window, profile, QA-evidence, and context-discovery workflows. `pire-browser chat` provides a bounded AI Gateway-backed natural-language command loop when `AI_GATEWAY_API_KEY` is set, and the dashboard includes a non-streaming AI Chat panel using that same loop; streamed dashboard chat remains future work. |
| Core navigation and refs | Supported | Open, agent-friendly URL/active-tab reads including active-tab URL-backed `--llms`/markdown fetches, snapshot, refs, covered-click diagnostics, click, best-effort tap-as-click, best-effort swipe-as-scroll, double-click, hover, focus, select, check/uncheck, scroll, scroll-into-view, fill, type, press, focused keyboard edges, get, wait, active-page `setcontent` fixtures, and tab workflows are available. |
| Selectors and snapshots | Supported | CSS, text-style selectors, semantic locators, agent-browser-compatible bare `snapshot`, explicit legacy `snapshot -i`, compact output, snapshot text diffing, URL snapshot diffing, and screenshot pixel diffing are available. |
| Sessions, profiles, and state | Partial | Ordinary and named sessions use temporary Firefox profiles; namespaces isolate live sessions, temp roots, and restore directories. `--restore` persists all cookies plus origin-keyed localStorage with periodic/close autosave, validation guards, expiry, and optional AES-256-GCM encryption. Named profile sources run from immutable temporary snapshots; explicit profile paths are durable. Existing 0.2.x profiles are preserved with explicit usage, cache-clean, and delete tools. Legacy active-origin state remains readable. |
| Screenshots, files, and clipboard | Partial | Screenshots with default hidden native scrollbars and explicit `--hide-scrollbars false` opt-out, image-backed PDF evidence, temporary-by-default downloads with explicit durable directories, chunked uploads capped at 8 MiB per command, file-input uploads, page dropzone uploads, and clipboard helpers are available; selectable-text PDF export, native file picker control, directory upload, and browser-chrome drag state are not. |
| Network and configuration | Partial | Domain allowlists, Firefox proxy settings, launch args, User-Agent overrides, headers, session-memory HTTP Basic credentials, best-effort offline request blocking, best-effort viewport/device/geolocation settings, `open/goto/navigate --device` first-navigation device presets with request User-Agent and page-level navigator/touch shims, network request/response waits, diagnostics with redacted headers, redacted/truncated outgoing request bodies, and bounded text-like response previews when Firefox exposes them, HAR start/stop/export, route mocks, and config defaults are available with documented Firefox limits. |
| Security guardrails | Partial | Domain, action, confirmation, content-boundary, output-size guardrails, optional encrypted state files, a built-in AES-256-GCM encrypted auth vault, agent-browser-compatible credential-provider plugins for one-shot auth login, CLI `plugin add/list/show`, CLI `plugin run` for `command.run` plus custom capabilities, automatic `launch.mutate` execution for local Firefox `launch.args`, `launch.userAgent`, and pre-navigation `launch.initScripts`, and MCP `pire_browser_plugin_list/show` discovery are available; `launch.extensions` and `browser.provider` remain unsupported by the Firefox backend. |
| Debugging and observability | Partial | Console, errors, best-effort JavaScript dialog handling, highlight, Firefox trace QA bundles, Firefox Performance Timeline profiler bundles, screenshot-sequence recording bundles including `record restart`, best-effort Web Vitals, best-effort React Fiber tree/inspect/render recording/Suspense, doctor, status, session inspection, recent redacted command activity, `stream enable/status/disable`, and the local status/session/activity dashboard with polling preview plus WebSocket screenshot-frame streaming and basic remote input are available; native WebM/video recording, streamed chat updates, Chrome DevTools traces/screencast, and Chrome CPU profiling are not. |
| Cloud providers and alternate engines | Not supported | CDP, cloud browser providers, Chrome engine mode, Lightpanda, and iOS simulator support are not in the current package. |
